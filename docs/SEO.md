# SEO & Growth Playbook

AdaptiveRAG-X should grow through useful engineering content, reproducible benchmarks and shareable demonstrations—not keyword stuffing or unsupported performance claims.

## Primary Topic Cluster

- Adaptive RAG
- Retrieval-Augmented Generation
- Agentic RAG
- Hybrid RAG
- BM25 vs dense retrieval
- RAG reranking
- Multi-hop RAG
- GraphRAG
- RAG evaluation
- Grounded generation
- Production RAG architecture
- Cost-aware LLM applications

## Page Strategy

| Page | Search intent | Primary conversion |
|---|---|---|
| Adaptive RAG guide | educational | GitHub star/fork |
| Hybrid RAG guide | implementation | example usage |
| RAG evaluation | technical | benchmark adoption |
| Reranking guide | implementation | configuration |
| Graph/multi-hop guide | advanced | contributor interest |
| Production deployment | transactional | deployment |
| Benchmark | comparison | trust/shareability |
| Cookbook | practical | copy/fork |

## Content Rules

1. Answer the user's technical question before promoting the repository.
2. Link every conceptual article to runnable code.
3. Publish measured benchmark methodology and limitations.
4. Use descriptive titles and headings that match developer search intent.
5. Add canonical URLs and descriptive metadata when these pages are published on a documentation site.
6. Add Open Graph and social preview metadata to the documentation site.
7. Generate `sitemap.xml` and `robots.txt` for the public documentation domain.
8. Keep code examples executable and versioned.
9. Avoid duplicate pages targeting the same query.
10. Refresh benchmark and integration pages when implementations materially change.

## Growth Loop

```text
Search intent
  -> useful guide
  -> runnable example
  -> benchmark
  -> GitHub repository
  -> issue/discussion
  -> contribution
  -> new feature
  -> new documentation
  -> new search surface
  -> repeat
```

## Social / Launch Assets

Prefer concrete assets:

- short architecture walkthroughs
- router decision screenshots
- before/after retrieval comparisons
- benchmark tables
- latency/cost experiments
- small reproducible demos
- release notes with measurable changes
- contributor-friendly issues

Do not manufacture engagement, fake benchmark results or claim guaranteed virality. Sustainable open-source growth comes from utility, credibility and repeated distribution.
